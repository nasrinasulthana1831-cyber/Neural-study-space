# Study Planner

A static, responsive study planner PWA. It keeps accounts, subjects, and tasks in the current browser's local storage. The AI Study Assistant includes a clearly labelled local demo mode and can call a separately hosted backend when configured.

The sign-in screen includes a custom Three.js study scene loaded as an ES module from jsDelivr. An internet connection is needed the first time the scene loads; the service worker caches the library after it loads. A CSS illustration remains available if WebGL or the CDN is unavailable.

The dashboard derives its plan, deadline calendar, and subject progress from your existing tasks and subjects. The optional 25-minute focus timer records only completed sessions in a separate `studyPlanner_sessions` browser-local storage key; those records power the focused-time and streak metrics. Existing account, subject, and task records are not migrated or replaced.

## Run in VS Code

This project does not use `package.json`, npm, or a build step.

1. Open this folder in VS Code.
2. Open `index.html` and use the VS Code Live Server extension to serve it on localhost.
3. Open the localhost URL in your browser and sign in or create a local planner account.
4. Stop Live Server from the VS Code status bar when finished.

If Python is installed, an alternative is `py -m http.server 8000` in the integrated PowerShell terminal, then open `http://localhost:8000`.

Serving the files on localhost enables the service worker and PWA behavior. The app can also be previewed with the VS Code Live Server extension.

## AI Assistant Modes

By default, the assistant is in **Demo mode**. Replies are generated locally from the current planner data; they are not generated by an AI model. No network request is made for chat messages in this mode.

To connect a real model, deploy a backend endpoint over HTTPS and set `AI_API_ENDPOINT` near the top of `script.js` to its URL, for example `/api/study-assistant` for a same-origin endpoint. The browser sends a JSON `POST` request with this shape:

```json
{
	"message": "Help me plan my study session",
	"history": [
		{ "role": "user", "content": "..." },
		{ "role": "assistant", "content": "..." }
	],
	"context": {
		"subjects": ["Biology"],
		"pendingTasks": [
			{ "title": "Review cells", "subject": "Biology", "deadline": null }
		]
	}
}
```

The endpoint must return JSON in this shape:

```json
{ "reply": "A concise response from your assistant." }
```

The backend should validate message length and input types, authenticate and rate-limit requests, and call the AI provider using a key stored only in a server environment variable or secret manager. Never add a provider key to `script.js`, HTML, or any other browser-delivered file. If hosting the endpoint on another origin, configure HTTPS and narrowly scoped CORS. Planner context is sent with each configured-backend request, so disclose and protect that data appropriately.

No backend or provider is included in this static project. Configuring `AI_API_ENDPOINT` only connects the frontend to your endpoint; you must implement and deploy that endpoint and configure its provider key on the server. The current browser-local account system is for personal/local use, not server-side authentication; a hosted service needs real backend authentication and must not trust the client-provided planner context.
